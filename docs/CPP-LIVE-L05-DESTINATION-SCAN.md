# L05 text destination scan

**Snapshot:** `develop` at `c845deb9` (2026-11-03). This is a source audit; it makes no code changes.

## Scope and result

The scan covered owned C++ headers and sources under `src` and `compat/win32`. It checked the maintained text-copy manifest, formatter and UTF-8 copy APIs, direct standard-library character copies, fixed text fields, and compatibility API output buffers. The 306-entry text-copy manifest records completed migrations; its calls are not counted as remaining candidates.

There are no owned `strcpy`, `strcat`, `strncpy`, or `strncat` calls. The formatter inventory contains 626 callsites plus the two span-wrapper declarations: 432 `CchSprintf` calls and 194 `CchSnprintf` calls, including the injectable `pfnCchSnprintf` calls. Every entry is classified as a bounded span/view destination. Each row records file, line, enclosing function, destination expression and capacity, and formatter failure/truncation behavior in [the CSV inventory](</Users/jdrake/Projects/sdl-stars/docs/CPP-LIVE-L05-FORMATTER-DESTINATIONS.csv>).

The rows classify as bounded span destinations. `CchSprintf` limits output to the span and 1024 bytes, retains a terminated complete UTF-8 prefix on truncation, and clears the destination on format/allocation failure. `CchSnprintf` is snprintf-style: it writes a NUL-terminated byte prefix, returns the required byte count, and can split a UTF-8 character if truncated. Its strict path/record callers must reject a result at or above capacity; display callers must prove the text fits or use the UTF-8-prefix formatter. The CSV captures each callsite so later work can verify that caller-side distinction.

## Follow-up

The scan found no unsafe legacy C string-copy call and no direct-copy candidate that currently bypasses a capacity check, a UTF-8 prefix boundary, or an explicit C ABI contract. The 195 `CchSnprintf` rows remain the actionable callsite checklist: verify each return-value use against its destination role. Strict paths and record text must reject truncation; display labels can retain a complete UTF-8 prefix. Pay particular attention to the unchecked label rows called out above.

The separate post-migration scratch-storage and borrowed-return audit remains open. This scan does not establish view lifetimes across callbacks, modal loops, or session teardown.
