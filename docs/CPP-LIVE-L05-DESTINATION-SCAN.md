## Scope and result

The scan covered owned C++ headers and sources under `src` and `compat/win32`. It checked the maintained text-copy manifest, formatter and UTF-8 copy APIs, direct standard-library character copies, fixed text fields, and compatibility API output buffers. The 306-entry text-copy manifest records completed migrations; its calls are not counted as remaining candidates.

There are no owned `strcpy`, `strcat`, `strncpy`, or `strncat` calls. The refreshed inventory contains 603 production formatter callsites plus two wrapper-contract rows: 455 `CchSprintf` calls, 141 direct `CchSnprintf` calls, and 7 injectable `pfnCchSnprintf` calls. Every entry is classified as a bounded span/view destination. Each row records file, current line, enclosing function, destination expression and capacity, and formatter failure/truncation behavior in [the CSV inventory](</Users/jdrake/Projects/sdl-stars/docs/CPP-LIVE-L05-FORMATTER-DESTINATIONS.csv>).

The rows classify as bounded span destinations. `CchSprintf` limits output to the span and 1024 bytes, retains a terminated complete UTF-8 prefix on truncation, and clears the destination on format/allocation failure. `CchSnprintf` is snprintf-style: it writes a NUL-terminated byte prefix, returns the required byte count, and can split a UTF-8 character if truncated. The original 186 snprintf-style candidates are resolved: 38 display/copy destinations now use UTF-8-prefix formatting or UTF-8-aware copy helpers, and all 148 remaining snprintf-style production callsites capture or conditionally consume the result and check it before strict use; bounded numeric/config values have explicit source bounds. No production snprintf-style return remains ignored. Display labels, prompts, and diagnostics use `CchSprintf` so a short destination ends at a complete UTF-8 boundary. The CSV records each call's source line and destination contract.
