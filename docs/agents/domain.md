# Domain docs

This repository uses a single context:
GLOSSARY.md at the root and numbered decisions in docs/adr/.

## Before exploration

Read GLOSSARY.md and ADRs relevant to the work.
If GLOSSARY-MAP.md is introduced, follow it to the relevant contexts.
Proceed silently when domain documents are absent; create them
lazily through domain-modeling as terms and decisions settle.

## Vocabulary and decisions

Use the glossary's terms when naming domain concepts.
Record unresolved terminology gaps for domain-modeling.
Surface conflicts with an existing ADR explicitly, naming the
decision and explaining why it should be reconsidered.
