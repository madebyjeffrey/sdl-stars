# Dialog template resources

All **34 canonical dialogs and 335 controls** are now embedded as standard
`RT_DIALOG` resources. Generated bytes match the Windows SDK resource compiler
output exactly. This is preparation for dialog creation; `CreateDialog`,
`DialogBox` and `EndDialog` are not implemented yet. Basic API coverage remains
**164/178 (92.1%)**.

## Generation and parsing

The UI resource generator reads the canonical `DIALOG`, `STYLE`, `CAPTION`,
`FONT` and `CONTROL` declarations. It preserves control IDs, signed coordinates,
style bits including `NOT WS_VISIBLE`, CP1252 text, font settings and DWORD
alignment. Unknown declarations fail the build instead of silently dropping
controls. No new build dependencies are needed.

The runtime parser validates the whole template before any window creation.
It reads little-endian fields without casting resource bytes to native
structures, converts UTF-16 text to the application's CP1252 strings, and
retains class/title ordinals and creation-data spans. Temporary strings and
control arrays are released on every failure path. Creation-data pointers
borrow the immutable module resource storage.

The layout follows Microsoft's [standard dialog template contract](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-dlgtemplate).
Extended dialog templates and Unicode text beyond CP1252 are outside the
current canonical resource scope. Dialog window creation, font-based unit
mapping, keyboard navigation, default buttons, initialization and modal
ownership are the next implementation work.

## Verification

`stars-compat-ui-resources` now parses all templates and rejects every truncated
prefix. The Windows target `test_win32_ui_resources_reference` compares every
generated resource byte against `res/stars.rc` compiled by windres. Select
the native target in CLion's `sdl-debug` profile to debug the parser.

```sh
cmake --preset sdl-debug
cmake --build --preset sdl-debug
xvfb-run -a ctest --test-dir dist/sdl-debug -R win32_ui_resources --output-on-failure
```

Address, undefined-behavior and leak sanitizer checks over the parser and its
malformed-input tests pass. SDL Debug and Release compatibility suites pass **39/39** each, and the
Windows SDK/unit suite passes **44/44**. The fresh tutorial failed at year
2424, page 62, instruction 489 after 265 actions when Stars exited
unexpectedly during fleet selection. The Wine log contains
`free(): invalid next size (fast)`; the failure origin is unresolved. Artifacts:
`dist/scaffold/tutorial/20261011T001752.829566Z`. The Windows tutorial does
not link this SDL runtime. Native regression matched all **519** reference
checkpoints, with 22 existing warnings and zero differences/errors or skipped
reference inputs. Game behavior and regression fixtures are unchanged.
